## 1. 배경: 왜 이 연구가 필요한가?

### 1.1 지식 그래프(Knowledge Graph)란?

지식 그래프는 **(head, relation, tail)** 형태의 트리플로 지식을 표현합니다.

```
예시:
(오바마, 태어난_곳, 하와이)
(오바마, 직업, 정치인)
(아인슈타인, 수상한_상, 노벨물리학상)
```

수학적으로: G = (E, R, T)
- E: 엔티티 집합 (오바마, 하와이, 아인슈타인, ...)
- R: 관계 집합 (태어난_곳, 직업, 수상한_상, ...)
- T ⊆ E × R × E: 트리플 집합

### 1.2 지식 그래프 임베딩(KGE)이란?

엔티티와 관계를 **저차원 벡터**로 표현해서, 새로운 트리플이 참인지 예측하는 기법입니다.

```
예: 오바마 → [0.1, 0.3, -0.2, ...]  (100차원 벡터)
    태어난_곳 → [0.5, 0.1, 0.4, ...]
```

**대표적인 KGE 모델들:**

| 모델 | 연도 | 점수 함수 | 아이디어 |
|-----|-----|---------|---------|
| TransE | 2013 | h + r ≈ t | 관계를 "이동"으로 해석 |
| DistMult | 2015 | h · r · t | 성분별 곱셈 |
| ComplEx | 2016 | Re(h · r · t*) | 복소수 임베딩 |
| RotatE | 2019 | h ∘ r ≈ t | 관계를 "회전"으로 해석 |

이 논문에서는 **DistMult**를 기본 점수 함수로 사용합니다:
```
score(h, r, t) = Σᵢ hᵢ × rᵢ × tᵢ  (각 차원별 곱의 합)
```

### 1.3 문제: 언제 예측을 믿을 수 있을까?

KGE 모델이 높은 점수를 주더라도, 그 예측을 **신뢰할 수 있는지** 알아야 합니다.

```
질문: (오바마, 주연_배우, ?)
→ 모델이 "톰 행크스"라고 답함
→ 이걸 믿어야 할까? ❌ (오바마는 배우가 아님!)
```

이것이 **OOD(Out-of-Distribution) 검출** 문제입니다:
- **ID (In-Distribution)**: 훈련 데이터와 비슷한 정상적인 질문
- **OOD (Out-of-Distribution)**: 이상하거나 처음 보는 패턴의 질문

### 1.4 불확실성 정량화 (Uncertainty Quantification)

"이 예측을 얼마나 믿을 수 있나?"를 **숫자로** 표현하고 싶습니다.

**일반적인 딥러닝에서의 접근법:**

| 방법 | 아이디어 | 한계 |
|-----|---------|-----|
| MC Dropout | 테스트 때 드롭아웃 여러 번 → 분산 계산 | 모델 불확실성만 포착 |
| Deep Ensemble | 여러 모델 학습 → 예측 분산 계산 | 계산 비용 높음 |
| Bayesian NN | 가중치에 분포 학습 | 학습 어려움 |

**지식 그래프에서는?**
→ 여기서 **GP-KGE**가 등장합니다!

## 2. GP-KGE: 확률적 지식 그래프 임베딩

### 2.1 GP-KGE란?

**GP-KGE** (Gaussian Process Knowledge Graph Embedding)는 2022년 Chen et al.이 제안한 방법입니다.

> **논문**: "Probabilistic Knowledge Graph Embeddings" (Chen et al., 2022)
>
> **핵심 아이디어**: 엔티티를 점(point)이 아닌 **분포(distribution)**로 표현하자!

**기존 KGE vs GP-KGE:**

```
기존 KGE:
  오바마 → [0.1, 0.3, -0.2]  (하나의 점)

GP-KGE:
  오바마 → N(μ, σ²)
         = N([0.1, 0.3, -0.2], [0.01, 0.02, 0.05])
           ↑ 평균 (위치)      ↑ 분산 (불확실성)
```

### 2.2 GP-KGE의 수학적 정의

각 엔티티 i에 대해 **가우시안 분포**를 학습합니다:

```
eᵢ ~ N(μᵢ, diag(exp(ℓᵢ)))

여기서:
- μᵢ ∈ ℝᵈ: 평균 벡터 (엔티티의 "위치")
- ℓᵢ ∈ ℝᵈ: 로그 분산 벡터 (불확실성)
- d: 임베딩 차원 (보통 100~200)
```

**왜 log-variance (ℓ)를 사용하나요?**
- 분산은 항상 양수여야 함
- exp(ℓ)는 항상 양수 → 제약 조건 자동 만족
- 학습 안정성 향상

### 2.3 GP-KGE의 불확실성 계산

트리플 (h, r, t)의 불확실성은 **head와 tail의 평균 분산**으로 정의됩니다:

```
U_GP(h, r, t) = (σ̄²_h + σ̄²_t) / 2

여기서:
σ̄²_e = (1/d) Σⱼ exp(ℓ_e,j)  (차원별 분산의 평균)
```

**직관:**
- 자주 등장하는 엔티티 → 많은 훈련 신호 → 낮은 분산 → **확신 있음**
- 드물게 등장하는 엔티티 → 적은 훈련 신호 → 높은 분산 → **불확실함**

### 2.4 GP-KGE 학습 과정

```
1. 초기화: 모든 μ, ℓ를 랜덤 초기화

2. Forward pass:
   - 각 엔티티에서 샘플링: e ~ N(μ, exp(ℓ))
   - 점수 계산: score = h · r · t (DistMult)

3. Loss 계산:
   - 링크 예측 손실 (정답 트리플 점수 높이기)
   - KL 정규화 (분산이 너무 작아지지 않게)

4. Backprop으로 μ, ℓ 업데이트
```

**KL 정규화가 중요한 이유:**
- 없으면 모든 분산이 0으로 수렴 (과적합)
- 사전분포 N(0, I)와의 KL divergence로 정규화

## 3. 관련 연구 (Literature Review)

이 논문이 어디에 위치하는지 이해하려면, 기존 연구들을 먼저 살펴봐야 합니다.

### 3.1 지식 그래프 불확실성 연구

| 방법 | 연도 | 핵심 아이디어 | 한계 |
|-----|-----|-------------|-----|
| **UKGE** | 2019 | 트리플마다 신뢰도 점수 학습 | 트리플 수준 → 엔티티 불확실성 포착 못함 |
| **BEUrRE** | 2021 | Box 임베딩, 박스 크기 = 불확실성 | 여전히 relation-agnostic |
| **GP-KGE** | 2022 | 엔티티를 가우시안으로 표현 | **relation-agnostic** (이 논문의 출발점) |

**공통 한계**: 모든 방법이 **관계를 무시**합니다. 엔티티별로 하나의 불확실성만 학습.

### 3.2 일반 딥러닝의 불확실성 추정

| 방법 | 핵심 아이디어 | KG에서의 문제 |
|-----|-------------|-------------|
| **MC Dropout** (Gal & Ghahramani, 2016) | 테스트 때 드롭아웃 → 분산 계산 | 모델 불확실성만, 구조 무시 |
| **Deep Ensemble** (Lakshminarayanan et al., 2017) | 여러 모델의 예측 분산 | 마찬가지로 relation-agnostic |
| **Bayesian NN** | 가중치에 분포 학습 | 계산 비용 높음, 구조 무시 |

**실험 결과**: MC Dropout과 Deep Ensemble은 WN18RR (11개 관계)에서는 괜찮지만, YAGO3-10 (37개 관계)에서는 **랜덤보다 나쁨** (AUROC 0.11~0.26).

→ 관계가 많아질수록 "구조적 불확실성"이 중요해지는데, 이걸 못 잡음.

### 3.3 그래프 기반 불확실성

| 방법 | 핵심 아이디어 | 한계 |
|-----|-------------|-----|
| **Graph Posterior Networks** (Stadler et al., 2021) | 그래프 구조로 불확실성 전파 | 노드 분류용, KG 관계 다양성 무시 |
| **GGPN** (Chen et al., 2022) | GPN을 KG에 적용 | 모든 엣지를 동일하게 취급 (heterogeneous 무시) |

**문제**: 지식 그래프는 **이질적(heterogeneous)** 그래프입니다.
- "태어난_곳"과 "결혼_상대"는 완전히 다른 의미
- 이걸 같은 엣지로 취급하면 안 됨

### 3.4 Coverage의 기존 용도

Coverage (엔티티가 특정 관계에서 관찰됐는지)는 이전에도 사용됐지만, **불확실성 목적이 아니었습니다**:

| 용도 | 논문 | 목적 |
|-----|-----|-----|
| Negative Sampling | Sun et al., 2019 (RotatE) | 학습용 네거티브 샘플 생성 |
| 데이터셋 분석 | Toutanova et al., 2015 | 데이터셋 통계 분석 |

**이 논문의 새로운 관점**: Coverage를 **불확실성 신호**로 재해석!

## 4. 핵심 문제: GP-KGE의 한계

GP-KGE의 아이디어는 훌륭하지만, **치명적인 한계**가 있습니다.

### 4.1 근본적인 문제: 관계를 무시함 (Relation-Agnostic)

**GP-KGE는 엔티티당 하나의 분산만 학습합니다.**

```python
# GP-KGE 코드 (단순화)
entity_variance = torch.zeros(num_entities, dim)  # 관계 차원 없음!

def get_uncertainty(head, relation, tail):
    return entity_variance[head] + entity_variance[tail]  # relation 사용 안 함
```

### 왜 이게 문제인가? - 구체적 예시

오바마를 생각해봅시다:

| 관계 | 훈련 데이터에서 관찰? | 불확실성은? |
|-----|-------------------|-----------|
| 태어난_곳 | ✅ 많이 봄 | 낮아야 함 |
| 직업 | ✅ 봄 | 낮아야 함 |
| **주연_배우** | ❌ **한 번도 안 봄** | **높아야 함** |

**GP-KGE의 문제:**
- 오바마는 유명 엔티티 → 전체 분산이 낮음
- "주연_배우" 관계에서도 낮은 불확실성을 부여 → **잘못됨!**

```
GP-KGE:
σ²(오바마, 태어난_곳, ?) = σ²(오바마, 주연_배우, ?)  ← 같음!
                          ↑
                   둘이 달라야 하는데...
```

### 관계별 분산을 학습하면 안 되나?

이론적으론 가능하지만 **실용적으로 불가능**합니다:

```
필요한 파라미터 수:
FB15k-237 기준: 14,541 엔티티 × 237 관계 × 100 차원
= 3.4억 개 파라미터 (너무 많음!)
```

## 5. 해결책: 의미-구조적 분해

### 5.1 핵심 통찰

불확실성을 **두 가지로 분해**합니다:

| 구분 | 의미적 불확실성 (Semantic) | 구조적 불확실성 (Structural) |
|-----|------------------------|--------------------------|
| **정의** | 엔티티 임베딩이 얼마나 잘 학습됐나? | 이 엔티티가 이 관계에서 관찰됐나? |
| **측정 방법** | GP 분산 (σ²) | Coverage (c) |
| **특징** | 관계와 무관 | 관계별로 다름 |
| **장점** | 드문 엔티티 감지 | 새로운 관계 조합 감지 |

### 5.2 Coverage란?

매우 단순한 개념입니다:

```
c(엔티티, 관계) = {
    1, if 훈련 데이터에서 이 엔티티가 이 관계와 함께 등장
    0, otherwise
}
```

**예시:**

| 트리플 | c(head, r) | c(tail, r) |
|-------|-----------|-----------|
| (오바마, 태어난_곳, 하와이) | 1 | 1 |
| (오바마, 주연_배우, ???) | 0 | ? |

### 5.3 왜 둘 다 필요한가? - 상호보완성

**Case 1: Coverage는 맞고, GP는 틀림**
```
상황: 유명한 엔티티인데, 특정 관계에서는 처음 봄
예: (오바마, 주연_배우, ???)

- GP: "오바마는 유명함 → 낮은 불확실성" ❌
- Coverage: "주연_배우 관계에서 오바마 처음 봄 → 높은 불확실성" ✅
```

**Case 2: GP는 맞고, Coverage는 틀림**
```
상황: 드문 엔티티인데, 우연히 이 관계에서 한 번 등장
예: (???, 태어난_곳, 작은마을X)
    ← 작은마을X는 드문 엔티티지만 "태어난_곳"에서 한 번 등장

- Coverage: "이 관계에서 봤음 → 낮은 불확실성" ❌
- GP: "드문 엔티티 → 높은 불확실성" ✅
```

**결론: 둘 다 필요하다!**

## 6. CAGP 알고리즘

### CAGP = Coverage-Augmented GP-KGE

두 신호를 단순히 선형 결합합니다:

```
U_CAGP(h, r, t) = α × U_GP + (1-α) × U_cov

여기서:
- U_GP = (σ²_head + σ²_tail) / 2  (정규화된 GP 불확실성)
- U_cov = 2 - c(h,r) - c(t,r)     (Coverage 불확실성, 0~2 범위)
- α ∈ [0, 1]                      (학습 가능한 혼합 계수)
```

### 구현 세부사항

```python
class CAGP(GP_KGE):
    def __init__(self, num_entities, num_relations, dim):
        super().__init__(num_entities, num_relations, dim)

        # 추가되는 것: Coverage 행렬 + alpha 파라미터
        self.coverage = precompute_coverage(train_data)  # [E × R] 이진 행렬
        self.alpha_logit = nn.Parameter(torch.tensor(0.0))  # 학습 가능

    def get_uncertainty(self, head, relation, tail):
        # GP 불확실성 (정규화)
        u_gp = self.get_gp_uncertainty(head, tail)
        u_gp_normalized = normalize(u_gp)

        # Coverage 불확실성
        c_head = self.coverage[head, relation]
        c_tail = self.coverage[tail, relation]
        u_cov = 2 - c_head - c_tail

        # 결합
        alpha = torch.sigmoid(self.alpha_logit)
        return alpha * u_gp_normalized + (1 - alpha) * u_cov
```

### 왜 이렇게 단순한가?

1. **Coverage는 이미 훈련 데이터에서 계산 가능** (학습 불필요)
2. **추가 파라미터는 α 하나뿐** (과적합 위험 낮음)
3. **알고리즘의 핵심은 "분해"라는 통찰**이지, 복잡한 모델이 아님

## 7. 이론적 기여

### Theorem 1: Coverage AUROC 공식

Coverage만으로도 AUROC를 **수학적으로 예측**할 수 있습니다.

```
AUROC_cov = (1/2) × [a(1 + s_r) + s_r × b]

여기서:
- a = P(head와 tail 둘 다 covered | ID 트리플)
- b = P(정확히 하나만 covered | ID 트리플)
- s_r = 관계 r의 희소성 = 1 - (해당 관계와 연결된 엔티티 수 / 전체 엔티티 수)
```

**검증 결과:**

| 데이터셋 | 예측값 | 실제값 | 오차 |
|---------|-------|-------|-----|
| WN18RR | 0.681 | 0.657 | 3.6% |
| FB15k-237 | 0.815 | 0.821 | 0.7% |
| YAGO3-10 | 0.797 | 0.760 | 4.9% |

### Theorem 2: GP의 한계 (Relation-Agnostic)

GP 분산은 **구조적으로** 관계 정보를 학습할 수 없습니다.

```
증명:
1. GP-KGE의 분산 파라미터: entity_logvar[num_entities, dim]
2. 관계 차원이 없음 → 관계별로 다른 분산을 가질 수 없음
3. 이는 설계상의 한계이며, 구현으로 해결 불가능
```

### Theorem 3: 상호보완성

Coverage와 GP는 서로를 **대체할 수 없습니다**.

```
존재성 증명:
1. ∃ 경우: Coverage가 맞고 GP가 틀림 (유명 엔티티 + 새 관계)
2. ∃ 경우: GP가 맞고 Coverage가 틀림 (드문 엔티티 + 관찰된 관계)

→ 어느 쪽도 다른 쪽을 포함하지 않음
→ 둘 다 필요함
```

## 8. 실험 결과

### 데이터셋

| 데이터셋 | 엔티티 수 | 관계 수 | 특징 |
|---------|---------|--------|-----|
| WN18RR | 40,943 | 11 | WordNet 기반, 관계 적음 |
| FB15k-237 | 14,541 | 237 | Freebase 기반, 관계 많음 |
| YAGO3-10 | 123,161 | 37 | Wikipedia 기반, 엔티티 많음 |

### OOD 검출 성능 (AUROC)

| 방법 | WN18RR | FB15k-237 | YAGO3-10 |
|-----|--------|-----------|----------|
| MC Dropout | 0.808 | 0.430 | 0.259 |
| Deep Ensemble | 0.696 | 0.225 | 0.111 |
| Coverage만 | 0.657 | 0.821 | 0.760 |
| GP만 | 0.647 | 0.749 | 0.824 |
| **CAGP (ours)** | **0.871** | **0.960** | **0.942** |
| 시너지 | +32% | +17% | +14% |

### 핵심 관찰

1. **MC Dropout, Deep Ensemble은 관계 수가 늘면 성능 급락**
   - WN18RR (11개 관계): 0.808
   - YAGO3-10 (37개 관계): 0.259
   - → 구조적 불확실성을 못 잡기 때문

2. **어느 단일 신호도 항상 이기지 못함**
   - YAGO: GP (0.824) > Coverage (0.760)
   - FB15k-237: Coverage (0.821) > GP (0.749)
   - → 둘 다 필요하다는 증거

3. **CAGP는 모든 데이터셋에서 압도적**
   - 최소 14%, 최대 32% 시너지 효과

## 9. 이 연구의 새로움 (Novelty)

### 9.1 기존 연구와의 차별점

| 관점 | 기존 연구 | 이 논문 |
|-----|---------|--------|
| **불확실성 관점** | 단일 값으로 학습 | **분해**: 의미적 + 구조적 |
| **관계 정보** | 무시 (relation-agnostic) | 명시적으로 활용 |
| **Coverage 용도** | 네거티브 샘플링, 데이터 분석 | **불확실성 신호**로 재해석 |
| **이론적 분석** | 경험적 결과 위주 | AUROC 닫힌 형태 공식 제공 |

### 9.2 왜 이전에 발견되지 않았나?

1. **"학습하면 된다"는 믿음**
   - 기존: "충분히 학습하면 모델이 알아서 불확실성을 배울 것"
   - 문제: 구조적으로 불가능 (파라미터 공간 한계)

2. **단일 데이터셋 평가**
   - WN18RR만 보면 MC Dropout이 잘 됨 (0.808)
   - 관계 많은 데이터셋 (YAGO3-10)에서 실패 드러남

3. **Coverage를 "너무 단순하다"고 무시**
   - 학습하는 게 아니라서 연구 가치가 없다고 봄
   - 실제로는 **학습 불가능한 정보**를 제공

### 9.3 핵심 기여 요약

```
1. [문제 발견] GP 분산은 구조적으로 relation-agnostic
   → 기존 방법들의 한계를 이론적으로 설명

2. [새로운 프레임워크] 의미-구조적 분해
   → 불확실성을 체계적으로 이해하는 틀 제공

3. [이론적 결과] Coverage AUROC 닫힌 형태 공식
   → 4% 이내로 정확하게 예측

4. [실용적 알고리즘] CAGP
   → 파라미터 1개 추가로 14-32% 성능 향상
```

### 9.4 Reviewer가 물을 수 있는 질문

**Q: Coverage는 너무 단순한 baseline 아닌가요?**

A: 단순함이 핵심입니다:
- GP가 구조적으로 학습 **불가능**한 정보를 제공
- 학습 없이도 AUROC를 예측 가능 (Theorem 1)
- 복잡하게 만들 필요가 없음

**Q: 더 복잡한 결합 방식은 안 되나요?**

A: 시도했지만 개선 없음:
- MLP로 결합: 비슷한 성능, 해석 어려움
- Attention: 과적합 위험
- 선형 결합이 충분함 (Occam's Razor)

**Q: 다른 OOD 정의에서도 작동하나요?**

A: 이 논문은 "random tail corruption" 설정
- 가장 표준적인 OOD 정의
- 다른 설정 (relation corruption 등)은 future work

## 10. 핵심 수식 정리

### GP 불확실성 (기존)

```
U_GP(h, r, t) = (σ²_h + σ²_t) / 2

- σ²_e: 엔티티 e의 학습된 분산
- 문제: r이 수식에 없음 (relation-agnostic)
```

### Coverage 정의

```
c(e, r) = 1  if ∃(h, r, t) ∈ Train: h=e or t=e
        = 0  otherwise
```

### 구조적 불확실성

```
U_cov(h, r, t) = 2 - c(h, r) - c(t, r)

- 범위: [0, 2]
- 0: 둘 다 이 관계에서 관찰됨
- 1: 하나만 관찰됨
- 2: 둘 다 처음 봄
```

### CAGP 불확실성

```
U_CAGP(h, r, t) = α × Ũ_GP(h, r, t) + (1-α) × U_cov(h, r, t)

- Ũ_GP: 정규화된 GP 불확실성 (U_cov와 스케일 맞춤)
- α: 학습 가능한 혼합 계수 (보통 ~0.5로 수렴)
```

## 11. 자주 묻는 질문

### Q1: Coverage는 너무 단순한 거 아닌가요?

단순하지만 **이론적으로 정당화**됩니다:
- Theorem 1에서 Coverage만으로 AUROC를 예측 가능
- GP가 못 잡는 구조적 패턴을 정확히 포착
- 학습이 필요 없어서 과적합 위험 없음

### Q2: 왜 두 신호를 단순히 더하나요?

1. **이론적 상호보완성**: 두 신호가 서로 다른 정보를 제공
2. **실험적 검증**: 학습된 α가 ~0.5로 수렴 (동등한 기여)
3. **Occam's Razor**: 단순한 방법이 효과적이면, 복잡하게 만들 필요 없음

### Q3: 다른 KGE 모델에도 적용 가능한가요?

네! CAGP는 **모듈화된 접근법**입니다:
- 기본 KGE 모델 (DistMult, TransE, RotatE 등) 위에 추가 가능
- 불확실성 계산만 수정, 점수 함수는 그대로

### Q4: Link Prediction 성능은 어떤가요?

**동일합니다.** CAGP는 불확실성 계산만 수정합니다:
- 엔티티/관계 임베딩: GP-KGE와 동일
- 점수 함수 (DistMult): 변경 없음
- 따라서 MRR, Hits@K 성능 동일

### Q5: 이 연구의 가장 중요한 기여는?

**알고리즘(CAGP)이 아니라 "분해(Decomposition)"라는 통찰입니다.**

기존 연구들이 왜 잘 안 됐는지를 **이론적으로 설명**:
- GP-KGE: 구조적 불확실성을 구조적으로 학습 불가
- MC Dropout, Ensemble: 마찬가지로 relation-agnostic

그리고 **해결책의 방향**을 제시:
- 의미적 + 구조적 신호를 분리해서 합쳐야 함
